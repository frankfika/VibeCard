# VibeCard 2.0 简明产品文档

> 这是当前产品真相源。  
> 原则：简单、有趣、能打动人。  
> 比赛版用微信小程序完成闭环；长期产品是完全开源、可自托管、跨平台的个人 AI 分身系统。

---

# 1. 一句话

**VibeCard 是一张会越来越懂你的 AI 名片。**

你平时和自己的分身聊天，它慢慢记住你的经历、口味、想法和边界。

别人打开你的 VibeCard，不会立刻拿到联系方式，而是先和你的分身聊聊。真正理解你、和你同频的人，才有机会与你建立联系。

> **先理解，再认识。**

---

# 2. 最重要的产品感觉

用户第一次使用时应该觉得：

> 原来我不用重新填一份简历，聊几句，它就把我说清楚了。

用户持续使用时应该觉得：

> 它居然记得我之前说过的事，而且越来越懂我了。

访客打开 Card 时应该觉得：

> 这不是一张死名片，我真的可以通过它认识这个人。

连接发生时应该觉得：

> 我不是通过了一场考试，而是真的被理解了。

# 3. 产品关系

整个产品只有四个东西：

## 3.1 我的 Vibe

只属于我的私人 AI。

我可以随时和它聊天：

- 最近在做什么
- 今天有什么新想法
- 我喜欢或不喜欢什么
- 最近想认识什么样的人
- 哪些事情不希望陌生人知道

每聊一次，它都更了解我一点。

## 3.2 我的 VibeCard

我的 Vibe 面向外界的一扇窗。

Card 展示的不是完整简历，而是：

- 我是谁
- 我现在在做什么
- 我在意什么
- 我能帮助别人什么
- 我最近想遇见谁
- 我确认公开的个人主页、作品和项目链接

## 3.3 我的 Now

Card 上一小段由我确认发布的最近动态。

它可以是：

- 最近在做什么
- 新完成了什么
- 最近在关注什么问题
- 正在寻找什么人、资源或合作
- 当下可以提供什么帮助

Now 不是公共朋友圈，也不是社区 Feed。没有关注流、推荐流、点赞排名和发布压力。它只是让一张名片保有时间感，让访客知道“这个人最近正在发生什么”。

Vibe 可以从私人对话中提议：

> 这件事要不要放到你的最近动态？

只有主人确认后才能发布。主人可以修改、隐藏、归档或删除；过期内容不能继续被分身当成当前事实。

## 3.4 一次连接

访客先和我的 Vibe 交流。

如果访客真正理解我、表达具体、双方有共同点，我的 Vibe 会把这次联系推荐给我。

最终是否认识，由我决定。

# 4. 比赛版只做四个页面

## 页面一：我的 Card

展示和分享自己的 VibeCard。

核心内容：

- 头像和名字
- 此刻的我
- 最近动态（默认展示最近三条）
- 我能帮什么
- 我想遇见谁
- 三个代表作品

核心按钮：

- 和我的 Vibe 聊聊
- 编辑
- 分享

## 页面二：我的 Vibe

一个极简聊天页面。

用户不需要进入“训练中心”，正常聊天就是训练。

Vibe 偶尔会问一个轻巧的问题：

> 你最近反复想到的一件事是什么？

> 什么样的合作邀请会让你立刻感兴趣？

> 最近有什么变化，值得放到你的 Card 上？

当它发现一件真正值得长期记住的事时，会先提出一个候选：

> **这件事值得记住：你最近更想认识真正做过 AI 社交产品的人。**

用户可以：

- 记住
- 改一下
- 别记这个

只有用户点击“记住”（或修改后确认）之后，Vibe 才会说：

> **我记住了：你最近更想认识真正做过 AI 社交产品的人。**

## 页面三：访客与分身

访客从 Card 点击：

> **先和我的分身聊聊**

分身可以：

- 回答关于主人的问题
- 解释主人最近在做什么
- 帮访客找到可能的共同点
- 询问访客为什么想认识主人

默认不超过 6 轮，不做通用聊天机器人。

## 页面四：联系请求

主人看到：

- 对方是谁
- 为什么想认识我
- 我们可能有什么共同点
- 我的 Vibe 为什么觉得值得聊

操作只有：

- 认识一下
- 以后再说
- 暂不联系

# 5. 第一次使用

不做六步表单，不做复杂人格测试。

用户第一次打开直接开始生成，不需要先选择云服务、运行时或部署方式。

用户可以先放入最多三个确认公开的 HTTPS 链接，例如个人主页、
GitHub、作品集或代表项目；链接只作为公开入口，不自动授权读取私人内容。
随后完成一段三分钟对话。

Vibe 依次问：

1. 你最近主要在做什么？
2. 哪件作品或经历最像你？
3. 你可以帮别人解决什么？
4. 你最近想认识什么样的人？
5. 有什么事情不希望我对陌生人说？

然后生成 Card：

> 我试着把此刻的你写成了一张 Card，看看像不像你。

用户确认或修改后直接发布。

发布完成后立即获得可分享链接。自己的域名、自托管服务和完整数据迁移
属于发布后的可选能力，不能阻塞第一次生成。产品对用户的承诺是：数据可
导出、Card 可搬家、公开链接不依赖唯一的中央账户。

原有结构化编辑器继续保留，作为精细调整入口。

# 6. 分身怎样越来越懂我

不在首版训练模型，也不让用户配置复杂参数。

分身通过三种方式成长：

## 6.1 和我聊天

一次回复最多提取一个“可能值得记住”的内容；不是每次聊天都需要提取。

只有用户确认后才进入记忆。

## 6.2 看我的选择

当我处理联系请求时，分身会学习：

- 我愿意见什么样的人
- 我讨厌什么表达方式
- 我最近的时间愿意花在哪里
- 哪些边界不能越过

反馈只需要点一下，不要求解释长篇原因。

一次连接决定本身只是一条交互记录，不会自动变成长期记忆。Vibe 可以基于重复或明确的选择提议一条“口味”或“边界”记忆，仍然必须由主人确认后才能生效。

## 6.3 允许我纠正

所有记忆都可以：

- 查看
- 修改
- 暂停使用
- 删除

Vibe 可以变聪明，但不能变成一个主人无法控制的黑箱。

# 7. 记忆设计

首版只需要四类记忆：

```text
事实：我做过什么
当下：我最近在做什么
口味：什么会打动我
边界：什么不能对外说
```

每条记忆有两个维度：

## 是否确认

- 待确认
- 已确认

## 谁可以使用

- 公开 Card 可见
- 分身可用于判断，但不能直接说
- 建立联系后可见
- 只有自己可见

首版不需要复杂知识图谱。

---

# 8. “打动分身”怎么做

它不应该像考试，也不应该显示 83 分。

分身只判断四件事：

1. 你是否真的理解主人
2. 你为什么偏偏现在想认识他
3. 你们是否有具体共同点
4. 这次认识有没有值得发生的下一步

当表达太泛时，分身可以追问：

> 你说想交流 AI，可以再具体一点吗？方辰最近更关心 AI 如何改变人与人的关系。

当发现强共同点时：

> 你们都在做个人 AI，而且都认为 AI 不应该替代真实关系。我觉得这值得让他看到。

给主人看的不是分数，而是：

> **我觉得你们值得聊一次。**

原因：

- 对方认真了解过 VibeCard
- 对方已经做过一个微信 AI 产品
- 双方都在研究个人分身的隐私边界

仍不确定：

- 对方更想合作还是只交流想法

# 9. 有趣从哪里来

不做小游戏，也不靠签到和积分。

有趣来自四个瞬间：

## 9.1 它第一次说中我

> 我发现你嘴上说想认识投资人，但真正让你兴奋的总是产品创造者。

## 9.2 它记住一个小细节

> 上次你说不喜欢泛泛的“资源互换”，这次我没有推荐类似请求。

## 9.3 它帮两个人发现共同点

> 你们都曾经因为“加了微信却再没说话”而想做关系产品。

## 9.4 Vibe matched

双方确认连接时：

> **Vibe matched.**  
> 你们因为一个具体的理由认识了彼此。

这就是产品的情绪奖励，不需要额外游戏系统。

# 10. 产品语气

Vibe 应该：

- 温暖
- 聪明
- 有一点自己的观察
- 不谄媚
- 不像客服
- 不像招聘筛选机器人
- 不随便给人下结论

推荐语气：

> 我大概懂了，但还差一个具体的理由。

> 这个问题他没有授权我回答，你可以留给本人。

> 你们现在不一定需要合作，但可能值得互相知道。

避免：

> 您的匹配度为 87%。

> 恭喜您通过资格审核。

> 根据大数据分析，你们高度适配。

# 11. 桌面端：Vibe Pet

桌面端放在比赛后的版本，但从一开始共用同一份记忆。

## 11.1 形态

它可以是一个很轻的桌宠：

- 常驻菜单栏或桌面角落
- 点一下展开一个小对话框
- 不需要打开完整应用
- 可以拖入一段文字、链接或文件
- 可以语音说一句近况

## 11.2 日常互动

用户点一下就可以：

- 问一个问题
- 记录一个想法
- 复盘今天
- 更新自己的 Card
- 看看谁想认识我

Vibe 偶尔主动问一句，但不能频繁打扰：

> 今天发生了什么，是未来的你可能想记住的？

> 你最近的关注点变了，要不要更新 Card？

## 11.3 模型配置

高级设置可以支持：

- 默认云端模型
- 用户自己的 API Key
- 本地模型
- 私有化模型服务

普通用户不需要在第一次使用时看到模型配置。

## 11.4 与 VibeCard 的关系

```text
桌面 Vibe Pet
    |
持续聊天与记忆
    |
私人 Vibe
    |
选择性投射
    |
公开 VibeCard
```

桌宠越了解主人，Card 和对外分身就越聪明。

# 12. 开源与多端策略

VibeCard 不是一个必须加入的中心化社区，也不依赖社区冷启动。

即使只有一个用户，它仍然可以帮助这个人：

- 和自己的 Vibe 对话
- 管理确认过的记忆
- 更新 Card 与 Now
- 分享一个可交互的公开分身
- 接收有具体理由的联系请求

开源版本必须能够独立运行。用户可以使用自己的模型、数据库、向量检索和知识库，也可以把整个系统部署到自己的设备或服务器。官方服务卖的是托管、同步、稳定在线和省心，不是锁住用户数据。

## 微信首发

- 微信小程序完成全部闭环
- Web 保留公开 Card 和分享落点
- 微信是比赛入口和中国市场的分享入口，不是产品边界

## 开源第二端：H5 / PWA

- 无需安装即可打开、创建和分享 Card
- 可以部署到自己的域名
- 支持自托管和官方托管
- 成为其他客户端共用的开放 Web 入口

## 后续客户端

- 桌面 Vibe Pet：本地资料、日常训练和快速记录
- iOS / Android App：通知、语音、离线与设备能力
- Embed / SDK：嵌入个人网站、GitHub、博客和其他产品
- 其他小程序或平台适配器：复用同一套 Core 与数据协议

## 原则

所有端共享：

- 同一份用户记忆
- 同一份 Card
- 同一个分身
- 同一个联系请求 Inbox

长期共享的不只是一个官方服务，而是一套开放协议和 Core：

- 同一套可版本化数据结构
- 同一套记忆确认与权限规则
- 可替换的模型、存储和检索接口
- 完整的数据导入、导出和删除
- 本地、用户自托管、官方托管三种运行模式

客户端负责各自平台体验，不能各建一套互不兼容的记忆系统。

# 13. MVP 技术简化

首版不需要：

- 模型微调
- 独立向量数据库
- 知识图谱
- 多智能体自动协商
- 关系上链
- 复杂推荐算法

首版只需要：

1. 微信云开发用户体系
2. 一个 AI 服务
3. 用户确认过的记忆
4. 简单的相关记忆检索
5. 联系请求
6. 结构化的推荐原因

加入 Now 后，比赛数据只保留六类：

```text
users
memories
cards
now_items
conversations
connection_requests
```

技术可以朴素，体验必须完整。

这些是比赛阶段的简化，不是长期锁定微信云开发。赛后首先抽离平台无关的 VibeCard Core，再增加本地存储、自托管服务、OpenAI-compatible 模型和可选向量检索适配器。

长期不重新发明向量数据库。VibeCard 开源的是数据库之上的个人 AI Memory Engine：

```text
原始对话与资料
-> 候选记忆
-> 主人确认
-> 权限与时效
-> 检索
-> Card / Now 公开投射
-> 访客分身与联系请求
```

# 15. 多个开发端怎么分工

## 端 A：微信小程序体验

负责四个页面和交互。

目录：

```text
packages/miniprogram/miniprogram/
```

## 端 B：数据与联系请求

负责用户、记忆、权限和请求。

目录：

```text
packages/miniprogram/cloudfunctions/
```

## 端 C：AI

负责 Card 生成、聊天、记忆提取和推荐原因。

目录：

```text
packages/shared/
packages/miniprogram/cloudfunctions/agent/
```

## 端 D：Web 和测试

负责 Public Card、Web 分身入口和端到端测试。

目录：

```text
packages/web/
```

比赛第一轮只约定了三个对象：

```text
VibeCard
Memory
ConnectionRequest
```

Now 在比赛增强阶段作为轻量公开投射加入，不为它建设 Feed、关注、评论或推荐系统。赛后再通过版本化 Core 契约开放模型、存储、检索和客户端适配器。

不要一开始设计几十个接口。

# 16. 三步开发

## 第一步：把故事做出来

使用假数据完成：

```text
公开 Card
-> 和分身聊
-> 提交联系理由
-> 主人看到请求
-> 认识一下
```

## 第二步：让它真的记住我

- 和我的 Vibe 聊天
- 提取一条记忆
- 用户确认
- 下次对话能正确使用
- Card 可以从记忆中更新

## 第三步：让它真的促成连接

- 访客对话
- 生成具体联系请求
- 分身解释为什么值得认识
- 主人开放联系方式

比赛前不扩展其他功能。

# 17. 90 秒演示

1. 用户和 Vibe 说：“我最近想认识真正做过 AI 社交产品的人。”
2. Vibe 提议一条记忆；用户点击“记住”，再预览并确认 Card 的“想遇见谁”更新。
3. 评委扫码打开 Card，问分身：“他为什么做这个？”
4. 分身基于真实记忆回答。
5. 评委说明自己做过一个 AI 小程序，想交流隐私边界。
6. 主人收到请求：“我觉得你们值得聊一次。”
7. 主人点击“认识一下”。
8. 页面显示：

> **Vibe matched.**

结束语：

> **AI 时代，我们不需要更多联系人。  
> 我们需要更少被错过的关系。**

# 18. 最终判断

比赛版先验证两个问题：

1. 用户是否觉得这个分身真的越来越懂自己？
2. 访客是否愿意先被理解，再与真人建立联系？

只要这两个时刻做得足够好，VibeCard 就已经是一个完整、AI Native、能打动人的产品。

其他东西以后再长出来。

长期再验证第三个问题：

3. 用户是否愿意把自己的 AI 身份与记忆真正掌握在自己手中，并在微信之外继续使用？

VibeCard 最终不是“另一个 AI 社区”，而是任何人都可以运行、修改、分享和迁移的个人 AI 身份基础软件。
